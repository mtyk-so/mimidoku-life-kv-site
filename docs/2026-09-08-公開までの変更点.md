## 2. デプロイ経路が変わった

**`content/articles/*.md` を編集してpushすれば、Cloudflareがビルドして公開する。**手元での `wrangler pages deploy` は不要になった。

```
編集 → git push → Cloudflareが npm install → npm run build:release → public/ を配信
```

直接アップロードで作ったPagesプロジェクトは、後からGit連携に切り替えられない。そのためプロジェクトを新規に作り直した。旧プロジェクトは削除済み。

### 公開スイッチはPagesのビルドコマンド

| ビルドコマンド | 生成物 |
|---|---|
| `npm run build` | 確認版。`noindex,nofollow`、「リニューアル確認用」の帯、A8計測タグなし、`robots.txt` は全拒否 |
| `npm run build:release` | 公開版。上記が外れ、`robots.txt` は許可＋sitemapの記載、A8計測タグを1ページにつき1点出力 |

**現在は `build:release`。**非公開に戻したいときは、Pagesの設定でこの1行を `npm run build` に変えて再デプロイする。ローカルの `npm run build` は確認版を出すので、手元の `public/` と本番の内容は一致しない。

### `public/` の生成物はCloudflareが上書きする

リポジトリにコミットされている `public/` の中身は、ビルドで上書きされる。**手元でコミットした生成物は本番に反映されない。**本文の修正は必ず `content/` 側で行う。

## 6. Cloudflare Accessの既定が反転した

**これが今日いちばん影響範囲の広い変更。**独自ドメインが3時間開かなかった原因であり、対処のために設定を反転させた。

### 何が起きていたか

`All Workers` というAccessアプリケーション（宛先「すべてのWorkers」、ポリシー `Cloudflare account members`）が、アカウント内のWorkersとPagesを全部覆っていた。PagesはWorkers基盤の上で動くため、`*.pages.dev` もカスタムドメインもこの配下に入る。

見つけにくかった理由は、**このアプリの宛先表示が「すべてのWorkers」だけで、ドメイン名がどこにも出ない**こと。アプリ一覧を `mimidoku-life.com` で検索しても出てこない。

### わかったこと3つ

- **個別のBypassアプリは `*.pages.dev` には効くが、Pagesのカスタムドメインには効かない。**同じアプリの同じ宛先リストに両方を並べても、前者は200、後者は302になる
- **Accessアプリの削除は、開ける操作ではなく閉じる操作。**削除するとポリシーだけが消えてホスト名の紐づけは残り、対象は「管轄内だが許可なし」になって全員が締め出される。開けたいときは削除ではなく編集する
- 犯人のアプリは、302のLocationに埋まっているAUDを復号して特定するのが速い

```bash
curl -sI https://<host>/ | grep -i '^location:' | grep -o 'meta=[^&]*' | sed 's/meta=//' | cut -d. -f2 | tr '_-' '/+' | base64 -d
```

出てきたAUDを、各アプリの「追加設定 > AUDタグ」と突き合わせる。

### 対処と、その副作用

`All Workers` のポリシーを `Bypass` / `Everyone` に差し替えた。既定が入れ替わっている。

| | 2026-09-07まで | 2026-09-08以降 |
|---|---|---|
| 新しく作ったWorkers/Pages | ログイン画面（保護される） | **そのまま公開される** |
| 運用 | 公開したいものを開ける | **守りたいものを個別アプリで囲う** |

反転の前に `vault-dashboard-d7x.pages.dev` を個別アプリ（`Allow` + `Cloudflare account members`）で囲ってある。順序を逆にすると一瞬でも公開状態になる。

**今後Workersに非公開のツールを置くときは、作った直後に個別アプリを足す。**忘れると公開されたまま気づかない。

Vault側の記録は `notes/Cloudflare-Worker+KV構成メモ.md` と `D:\site\手順書-CloudflareKV構成.md` に反映済み。

## 8. 記事を追加する手順（現行）

1. `content/articles/<slug>.md` に本文を置く（先頭の `#` が記事タイトル）
2. `content/site.json` の `articles` に1件足す（`slug` / `category` / `date` / `description` / `image` / `imageAlt`）
3. 画像は `public/images/` に置く
4. `npm run build` でローカル確認（`npm start` → `http://127.0.0.1:4173/`）
5. コミットしてpush

sitemapとcanonicalは自動で更新される。手動の操作は要らない。
