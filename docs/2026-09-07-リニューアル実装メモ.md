## 原稿と生成ファイル

**Markdownを編集してビルドすると、静的HTMLが更新される。** 読者側でJavaScriptを動かさなくても全文を読める。既存のCloudflare Pagesの`public`配信を引き継ぐ構成である。

| ファイル | 役割 |
|---|---|
| `content/articles/kirawareru-yuki.md` | 本人提示の体験記事本文 |
| `content/articles/audible-beginners-guide.md` | 本人提示のガイド本文 |
| `content/site.json` | 記事の順序・カテゴリ・日付・紹介文・画像設定 |
| `tools/build-site.mjs` | トップと記事HTMLを生成 |
| `public/css/journal.css` | リニューアル用の共通デザイン |
| `public/index.html`、`public/articles/*.html` | 生成物。本文の修正はMarkdown側で行う |

原稿はVaultからコピーしたもの。冒頭の管理情報と末尾の編集メモは含めず、本文の表現は保持した。Vault原稿との自動同期は行わない。Vaultで手直しした場合は、対応する`content/articles/`の本文にも反映する。サイトに出す内容と個人の編集メモを混在させない。

## ローカルで確認する

**通常のビルドは、写真準備中の表示とnoindex付きの確認版を生成する。** 今回の確認版HTMLは生成済みのため、最初に画面を見るだけなら`npm start`でよい。

```powershell
cd D:\site\mimidoku-life-kv-site
npm start
```

ブラウザで `http://127.0.0.1:4173/` を開く。原稿を変更して生成し直す場合は、初回に依存ライブラリをインストールする。

```powershell
npm install
npm run build
```

ビルドに使うMarkdownライブラリは`marked`。初回実装時はCodexの同一バージョンのバンドルで生成し、サイト内の`node_modules`は未作成。Node.jsは`marked`の必要条件を満たすバージョンを使用する。

## 写真の差し替え

**写真は3枠から用意できる。** 同じ写真を一覧と記事冒頭で共用するため、最初から大量の写真は必要ない。

| 枠 | 内容の例 | 比率の目安 |
|---|---|---|
| トップのメイン | 本やイヤホンのある机、リビング | 横長。PCで約3:1、スマホでは大きくトリミングする |
| 体験記事 | 実際に聴いた場所や散歩の風景 | 3:2 |
| 初心者ガイド | スマートフォンと本など | 3:2 |

`public/images/`に画像を保存し、`content/site.json`の`heroImage`・各記事の`image`へ`/images/ファイル名.jpg`などを設定する。`heroAlt`・`imageAlt`へ写真の説明も入力して再ビルドする。空欄の間は写真準備中の枠を表示する。

## 既存機能と公開前の仕上げ

**旧作品一覧とWorker/KVは保持し、リニューアルのトップからは実記事を案内する。** `public/works.html`、既存CSS/JS、データ、Worker、取り込みツールは今回変更していない。旧URLの公開時の扱いは後で決める。

2026-09-08に、トップと記事末尾へA8の案内欄を追加した。既存の`public/js/config.js`のテキスト素材URLと対応する計測URLをビルド時に読み込み、静的HTMLに反映する。案内ボタンはJavaScriptなしでも使える。ページ上部に広告表示を置き、リンクには`sponsored nofollow noopener noreferrer`を指定した。記事内の出典・公式ヘルプのリンクはそのまま。ローカル確認版では表示回数の計測画像を出さず、公開版ビルドで1ページにつき1点出力する。

写真、プロフィールの文章、広告リンク、旧作品一覧の扱いを画面と合わせて確認する。公開前にはガイドの料金・特典等を再確認する。公開用HTMLを生成するコマンドは次のとおりで、このコマンド自体はアップロードしない。

```powershell
npm run build:release
```

このビルドは確認用の帯とnoindexを外す。写真は別途設定が必要。実際の公開は既存のデプロイ手順で行う。

確認先は `http://127.0.0.1:4173/`。以前の4186番ポートはCodexの確認用コピーであり、サイト本体での編集は自動では同期しない。

記事タイトルはMarkdown冒頭の`#`の行、一覧の紹介文・カテゴリ・画像・日付は`content/site.json`で編集する。Vaultの元原稿には自動で反映されない。広告欄は共通テンプレートで出力するため、Markdown側へ複製する必要はない。A8の素材設定を変更したときも再ビルドする。
